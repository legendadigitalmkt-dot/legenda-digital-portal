# NÃO REPETIR — Portal

Consultar antes de iniciar algo semelhante. Fontes históricas: LL-002/003 no Learning Ledger; ciclo atual LL-005.

- Não chamar amostra parcial ou execução interrompida de cobertura integral.
- Não confundir timeout/hidratação/falha de harness com bug de produto sem reproduzir.
- Não exigir carregamento de imagem oculta em details fechado como leitura inicial.
- Não chamar workflow com publicação skipped de deploy.
- Não chamar configuração/instalação de prova de entrega de email.
- Não presumir que login do titular transfere uma sessão ao agente.
- Não expor credenciais, copiar sessões ou contornar restrições conhecidas.
- Não tratar QA como prova de demanda, conversão, pricing ou receita.
- Não misturar backends, Auth, analytics ou dados entre produtos.
- Não inventar créditos, fontes, campanhas ou números para preencher campos.
- Não tratar eventos como visitantes únicos.
- Não tratar evidência de 15/10 como estado verificado hoje.
- Não usar o projeto Lunior para testar/aplicar recursos do Portal quando a conexão correta não está autorizada.
- Não considerar ocultação de menu como autorização: verificar banco e rotas diretas.
- Não gravar corpos, respostas de ferramentas, emails, tokens ou config completa em auditoria genérica.
- Não reconstruir uma falsa trilha de auditoria de ações anteriores aos triggers.
- Não rebuildar dist enquanto um servidor de testes o está lendo.

Ausência de dados sobre canais, mensagens ou pricing não significa fracasso. Essas categorias continuam sem resultado suficiente, em vez de receber conclusões inventadas.


- Não congelar um patch de segurança independente de schema atrás de um bloqueio de acesso a outro marco.
- Limitar instrumentação/capturas ao fixture correto; verificar o escopo de substituições.
