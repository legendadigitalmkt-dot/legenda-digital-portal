## Consulta antes de construir
1. Ler DO-NOT-REPEAT.md e registros relacionados.
2. Consultar hipótese, fonte, data e decisão; revalidar fatos antigos quando necessário.
3. Consultar ativos reutilizáveis e seus limites.
4. Registrar a nova hipótese, público, problema, evidência, métrica e sucesso antes do resultado.
5. Fechar o ciclo com fato/interpretação/hipótese, decisão, confidence score, ativos e próximo teste.

## Fechamento / exportação aprovada
O responsável atualiza primeiro o registro completo do ciclo, revisa privacidade e evidência, atualiza os índices e referencia o commit/PR no ledger de continuidade. Mudanças nos resumos passam pela mesma revisão do PR. Nenhum dado privado, conta individual de visitante, credencial ou payload cru entra nesses documentos.

O módulo /admin/project-memory e a geração automatizada de documentação pertencem ao marco 7; não estão implementados nesta Foundation. Antes desse marco, definir contrato de aprovação, versionamento e conflitos. Não sobrescrever Git e banco como se houvesse sincronização bidirecional pronta.

Cross-project learning é somente candidato para HQ. Não envia dados individuais nem muda produtos de outros projetos. Nenhuma decisão transversal foi tomada pelo Dev.
